## Tokenizer–Organism Interaction Architecture Manual (Tkinter Canvas)

### Purpose

Generate a multi-file technical manual describing a structured architecture for implementing complex user interactions in Tkinter Canvas applications.

The manual must be:

* precise
* implementation-oriented
* structured for LLM consumption
* consistent across all sections

---

## Core Architecture (authoritative)

The system is composed of the following layers:

### RAW

* Contains input state for the current and previous frame
* Includes:

  * mouse position (x, y)
  * mouse button states
  * key states
  * time (seconds since start)
* RAW is explicitly stored as:

  * `current`
  * `previous`

---

### DERIVED (Tokenizers)

* Produced by tokenizers
* Represents interpreted perceptual facts
* Tokenizers may read:

  * RAW.current
  * RAW.previous
  * DERIVED.previous
* Tokenizers must:

  * NOT emit effects
  * NOT hold long-lived behavioral state
  * ONLY define perception (e.g., drag, hover, hit-testing)

---

### ORGANISMS

* Stateful processes (finite state machines)
* Operate over time
* May read:

  * RAW
  * DERIVED
* Must:

  * request permissions from Judge
  * emit **effects only**
* Must NOT:

  * directly modify world model
  * define perceptual logic (belongs to tokenizers)

---

### EFFECTS (output of organisms)

Two types:

#### Persistent Effects

* Modify world model
* Example:

  * SET_SELECTION(ids)
  * MOVE_NODE(id, dx, dy)

#### Volatile Effects

* Exist only for the current frame
* Used for projection overlays
* Example:

  * SHOW_MARQUEE(rect)
  * HIGHLIGHT(ids)

---

### WORLD MODEL

* Authoritative persistent state
* Contains:

  * objects (nodes, rectangles, edges)
  * positions, sizes
  * selection state
* Must ONLY be modified via persistent effects

---

### JUDGE

* Minimal arbitration system
* Manages resource locks (e.g., POINTER)
* Responsibilities:

  * grant or deny permission
  * track resource ownership
* Must NOT:

  * implement behavior logic
  * interpret input

---

### PROJECTION

Projection is a **reconciliation system** over a retained-mode canvas.

Inputs:

* world model (persistent)
* volatile effects (current frame)

Responsibilities:

1. compute desired visual state
2. compare with current canvas state
3. apply:

   * create
   * update
   * delete operations

Projection must NOT modify world model.

## Critical Invariants (must be enforced)

* Organisms emit only effects
* Tokenizers define all perception
* World model is mutated only via effects
* Judge is minimal and does not contain behavior logic
* Projection performs reconciliation, not immediate drawing

---

## Failure Modes Section

Must explicitly describe:

* tokenizers containing behavior
* organisms redefining perception
* judge becoming complex logic engine
* projection mutating world model
* duplication of perceptual logic
